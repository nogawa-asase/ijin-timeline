# 偉人の時代 - アイデアメモ

## このドキュメントの位置づけ

このドキュメントは壁打ち・ブレストの成果物で、正式な仕様書ではありません。

## プロダクトビジョン

偉人の名前を入れるだけで、その人が生きていた期間が西暦の横軸上に線で引かれるWebサービス。2人を並べて、「この2人って同じ時代を生きてたの？」という素朴な疑問に一瞬で答えたい。

**一言で言うと**: 偉人の「同時代かどうか」が一目でわかるタイムライン

---

## 解決したい課題

### 今困っていること

1. **生没年を並べて比べるのが面倒**
   - Wikipediaで1人目の生没年を調べて → 別タブで2人目を調べて → 頭の中で引き算
   - 紀元前と紀元後をまたぐと計算がややこしい
   - 3人以上になるともう無理

2. **数字だけだと時代の重なりがピンとこない**
   - 「1534年〜1582年」「1543年〜1616年」と言われても、重なりの長さが直感的にわからない
   - 「Aが何歳のときにBが生まれたか」まで考えるのは手間

3. **意外な同時代関係に気づけない**
   - 日本史と世界史を別々に習うので、同じ時代の人物だと気づかない
   - 「え、この2人って同じ時代なの！？」という驚きが、歴史を面白くするきっかけになるのにもったいない

4. **年表は固定された内容しか見られない**
   - 教科書や本の年表には、自分が比べたい人物の組み合わせが載っていない

## ターゲットユーザー

### ペルソナ1: 歴史好きの大人

- **年齢**: 30-50歳
- **職業**: 会社員など
- **経験**: 歴史の本やドラマ、動画が好き。スマホやPCの操作は普通にできる
- **今困ってること**:
  - 本やドラマを見ていて「この人とあの人って同じ頃？」と気になることがよくある
  - 調べるたびにWikipediaを行ったり来たりしている

- **欲しいもの**:
  - 名前を入れるだけでパッと比べられる
  - スマホでもサクッと使える
  - 誰かに「ほら見て」と見せられる

### ペルソナ2: 歴史を学んでいる子供とその保護者

- **年齢**: 小学校高学年〜中学生 / 保護者は30-40代
- **経験**: 学校で日本史・世界史を習い始めたところ
- **今困ってること**:
  - 人物名と年号がバラバラに頭に入っていて、つながりが見えない
  - 日本と世界の出来事を並べて考えるのが難しい

- **欲しいもの**:
  - 見た目でわかる、直感的な表示
  - 難しい操作なしで使える
  - 意外な発見があって楽しい

## 主要機能の候補

### P0 (MVPで絶対必要)

#### 1. 偉人名の入力と候補選択
- 入力欄は2つ
- 入力中にWikidataから候補を検索して表示(オートコンプリート)
- 同名人物を区別できるよう、候補に生没年と短い説明を添える

```
入力: 信長
候補:
  織田信長(1534–1582)日本の戦国大名
  織田信長(…)…
```

#### 2. 生存期間のタイムライン表示
- 横軸は西暦
- 表示範囲は「早いほうの生年〜遅いほうの没年」+左右に余白
- 人物ごとに色の違う横線を1本ずつ描画
- 線の端に生年・没年、線の上に名前を表示
- 2人の重なり区間は背景を塗って強調

#### 3. 同時代かどうかの結果表示
```
重なりあり:
  1543年〜1582年の約39年間、同じ時代を生きていました
  (織田信長が9歳のとき、徳川家康が生まれました)

重なりなし:
  Aの死後、約○年後にBが生まれました
```

#### 4. データの特殊ケースへの対応
- 紀元前の人物: 「前551年」のように表記
- 存命の人物: 現在の年まで線を引き、端を矢印で区別
- 生没年があいまいな人物(「1530年代」「6世紀頃」): 線の端を点線にする
- 没年データが欠けている人物: 「没年不明」と表示

### P1 (重要だけど後回しでもいい)

#### 5. URLでの共有
```
https://nogawa-asase.github.io/ijin-no-jidai/?a=Q171411&b=Q171977
# 開くと同じ比較結果が表示される
```

#### 6. 入力欄の追加
- 3人以上を並べて比較できるようにする
- 「+ 人物を追加」ボタンで欄を増やす

#### 7. タイムラインの見やすさ向上
- 世紀ごとの目盛り線や、調べる人物に合った時代区分の背景表示(日本の人物なら戦国時代・江戸時代、中国の人物なら王朝、ヨーロッパの人物ならルネサンスなど)
- 線をタップすると人物の詳細(説明文、Wikipediaへのリンク)を表示

### P2 (あったら嬉しい)

#### 8. 主な出来事の表示
- 人物の線の上に、主な出来事を点で表示(例: 本能寺の変)

#### 9. 同時代の有名人の提案
- 「この人と同じ時代の人物」をいくつか提案して、ワンタップで追加。日本史の人物を選んだら世界史の人物を、世界史の人物を選んだら日本史の人物を提案する(例: 織田信長 → エリザベス1世、レオナルド・ダ・ヴィンチ → 雪舟)

#### 10. 画像として保存
- タイムラインをPNG画像で保存して、SNSなどでシェアできる

#### 11. 人物の顔写真・肖像画表示
- Wikidataに登録されている画像を線の横に表示

### 既存の方法との比較

| 特徴 | 偉人の時代 | Wikipedia | 教科書・本の年表 | 自分で計算 |
|------|-----------|-----------|----------------|-----------|
| 好きな人物を選べる | ✅ | ✅ | ❌ | ✅ |
| 2人を並べて比較 | ✅ | ❌ | 部分的 | △ |
| 視覚的にわかる | ✅ | ❌ | ✅ | ❌ |
| 重なり期間を自動計算 | ✅ | ❌ | ❌ | ❌ |
| スマホで手軽 | ✅ | ✅ | ❌ | ❌ |
| 人物の詳しい情報 | 🚧 | ✅✅✅ | ✅ | ❌ |

### このサービスの強み

1. **名前を入れるだけ**
   - 調べる → 計算する → 比べる、の手間がゼロ
   - 登録もインストールも不要

2. **見た瞬間にわかる**
   - 数字ではなく線の重なりで、同時代かどうかが直感的にわかる
   - 年齢関係まで文章で補足

3. **ほぼすべての偉人に対応**
   - Wikidataのデータを使うので、有名人ならほぼ誰でも調べられる
   - 日本史も世界史も区別なく並べられる

4. **シンプル**
   - 機能を絞って、1ページで完結
   - 子供でも迷わず使える

## 技術的な検討事項

### データの取得方法

**候補1: Wikidataからブラウザで直接取得**
- 誰でも・ほぼすべての人物を調べられる
- APIが外部サイトからの呼び出しを許可しているので、GitHub Pagesだけで完結
- 表記ゆれや同名人物への対応が必要

**候補2: 自作の偉人リスト(JSON)を同梱**
- 確実で速い
- 載せた人物しか調べられない

**結論**: Wikidataから取得する

### Wikidata APIの使い方

- 候補検索: `wbsearchentities`(`language=ja`、`origin=*` を指定)
- 詳細取得: `wbgetentities`(候補のIDをまとめて渡す)
- 絞り込み条件: 人間である(P31がQ5)、生年月日(P569)がある
- 使う項目: 生年月日(P569)、没年月日(P570)、日本語ラベル、日本語説明
- 入力が止まって0.3秒後に検索(打鍵ごとに問い合わせない)

### 生没年データの読み方

- 日付は `+1534-06-23T00:00:00Z` 形式。年の部分だけ使う
- 紀元前は `-0551-...` のようにマイナス
- 精度情報: 9=年まで確か、8=年代、7=世紀。9未満はあいまい表示
- 値が複数ある場合: 「推奨」ランクの値を優先、なければ最初の値
- 西暦には0年がないので、紀元前と紀元後をまたぐ期間の計算では1年差し引く

### 描画方法

- タイムラインはSVGで描画
- 画面幅に合わせて縮尺を変える

### 技術構成

- HTML / CSS / JavaScript のみ(ビルドツールなし)
- 公開先: GitHub Pages
- リポジトリ名(仮): `ijin-no-jidai`

## 非機能要件(とりあえず)

### パフォーマンス
- 候補の表示: 入力が止まってから1秒以内
- タイムラインの描画: 人物を選んだら即座に反映

### 使いやすさ
- 小学生でも説明なしで使える
- スマホでもPCでも見やすい
- エラーメッセージがわかりやすい
  - 「該当する人物が見つかりませんでした」
  - 「データを取得できませんでした。時間をおいて試してください」

### 信頼性
- データの不確かさ(生没年があいまいなど)を隠さずに表示する
- 通信に失敗しても画面が壊れない

### 拡張性
- 入力欄の数を後から増やせる作りにしておく
- 出来事表示などの機能を追加しやすい構造にする

   - 2人のままか、3人以上に対応するか

   - 混雑時に遅くならないか、問い合わせ回数の制限にかからないか
