# プロダクト要求定義書 (Product Requirements Document)

## プロダクト概要

### 名称
**偉人の時代** - 偉人が「同じ時代を生きていたか」が一目でわかるタイムライン

### プロダクトコンセプト
- **名前を入れるだけ**: 偉人の名前を入力して候補から選ぶだけで、生没年を調べる・計算する・比べる手間がゼロになる
- **見た瞬間にわかる**: 西暦の横軸上に生存期間を線で引き、重なりの有無と長さを数字ではなく図で直感的に伝える
- **日本史も世界史も区別なく**: Wikidataのデータを使い、有名な人物ならほぼ誰でも、地域や時代をまたいで並べられる

### プロダクトビジョン
「この2人って同じ時代を生きてたの？」という素朴な疑問に、名前を入れるだけで一瞬で答えるWebサービスを提供する。
日本史と世界史を別々に学んできた人が、「え、この2人って同じ時代なの！？」という意外な発見に出会えるようにする。
登録もインストールも不要で、スマホでもPCでも、大人も子供も説明なしで使える。
その驚きをきっかけに、歴史をもっと面白く感じてもらうことを目指す。

### 既存の方法との違い

| 特徴 | 偉人の時代 | Wikipedia | 教科書・本の年表 | 自分で計算 |
|------|-----------|-----------|----------------|-----------|
| 好きな人物を選べる | ✅ | ✅ | ❌ | ✅ |
| 2人を並べて比較 | ✅ | ❌ | 部分的 | △ |
| 視覚的にわかる | ✅ | ❌ | ✅ | ❌ |
| 重なり期間を自動計算 | ✅ | ❌ | ❌ | ❌ |
| スマホで手軽 | ✅ | ✅ | ❌ | ❌ |
| 人物の詳しい情報 | 🚧(P1で説明文とWikipediaへのリンク) | ✅✅✅ | ✅ | ❌ |

人物の詳しい情報はWikipediaに任せ、本サービスは「比べる」ことに特化する。

### 目的
- 2人の偉人の生存期間を、入力から結果表示まで30秒以内で比較できるようにする
- 重なり期間(年数)と年齢関係(「AがX歳のときにBが生まれた」)を自動計算し、頭の中での引き算を不要にする
- 紀元前・存命・生没年があいまいといったデータの特殊ケースでも、不確かさを隠さず正しく表示する

  - 通勤中に歴史の本を読み、気になった2人をその場で比べる
  - 週末、家族との会話で「実は同じ時代だった」という話題をスマホで見せる

  - 教科書の年表には、自分が比べたい人物の組み合わせが載っていない

  - 難しい操作なしで使える
  - 意外な発見があって楽しい
- **典型的な利用シーン**:
  - 宿題や自主学習で、習った人物と同時代の人物を調べる
  - 保護者と一緒に、日本の人物と海外の人物を並べて驚く

## 成功指標(KPI)

本プロダクトは個人開発のため、アクセス解析による大規模な指標ではなく、品質と実際の利用者の反応を指標とする。

**MVPリリースの定義**: P0の機能をすべて `main` ブランチにマージし、GitHub Pages(`https://nogawa-asase.github.io/ijin-timeline/`)に反映された時点。

### プライマリーKPI
- **生没年の正確さ**: 検証用の有名な偉人20人で、表示される生没年が、その人物のWikidataに登録されている生年・没年(複数ある場合は採用ルールに従って選んだ値)と100%一致する(MVPリリース時点)
  - 検証用20人の条件: 日本史10人・世界史10人。紀元前の人物、存命人物、生没年があいまいな人物(年代・世紀単位)、没年不明の人物を各1人以上含む
  - 測定方法: 検証リスト(`docs/manual-test-checklist.md` に用意する)に沿って、画面の表示とWikidataの項目ページを手動で見比べる
  - 補足: データの正はWikidataとする。Wikidataの値そのものの誤り(Wikipediaとの食い違いなど)は本サービスでは修正しない(スコープ外を参照)
- **利用意欲**: 家族・友人5人以上に使ってもらい、そのうち3人以上が自分から2組以上の比較を試す(MVPリリース後1ヶ月以内)
  - 測定方法: 使っている様子の観察とヒアリング
- **驚きの体験**: 上記の5人のうち3人以上から「え、この2人って同じ時代なの！？」という反応が出る(MVPリリース後1ヶ月以内)
  - 測定方法: ヒアリング

### セカンダリーKPI
- **動作環境**: iPhone(Safari)、Android(Chrome)、PC(Chrome / Edge / Safari / Firefox)の各最新版で、主要な操作(入力・候補選択・タイムライン表示)が問題なく動く(MVPリリース時点)
  - 合格基準: 各環境で機能要件1〜4の受け入れ条件をすべて満たし、開発者ツールのコンソールにエラーが出ない
  - 測定方法: 各環境での手動テスト
- **説明なしでの操作**: 小学校高学年〜中学生2人以上が、説明なしで2人の比較を完了できる(MVPリリース後1ヶ月以内)
  - 完了の定義: 指定した2人を候補から選び、タイムラインと結果の文章が表示された状態にできること
  - 測定方法: 操作の観察
- **比較にかかる時間**: 上記の観察で、ページを開いてから比較が完了するまでの時間が、全員30秒以内である(MVPリリース後1ヶ月以内)
  - 測定方法: 観察時にストップウォッチで計測する(比べる2人はあらかじめ伝えておく)

## 機能要件

### コア機能(MVP)

#### 1. 偉人名の入力と候補選択

**ユーザーストーリー**:
歴史好きの大人として、比べたい人物を手早く正確に指定するために、名前の一部を入力すると候補が表示され、そこから選べる入力欄が欲しい

**受け入れ条件**:
- [ ] 画面に人物の入力欄が2つある
- [ ] 入力が止まってから0.3秒後にWikidataへ候補を問い合わせる(1文字入力するごとには問い合わせない)
- [ ] 正式な名前(例: 「徳川家康」)の先頭部分を入力すれば、目的の人物が候補に出る。名前の途中だけ(例: 「家康」)や別名(例: 「松平元康」)でヒットするかはWikidataの検索仕様に従う(今後の検討事項でプロトタイプ検証する)
- [ ] 候補は日本語で検索され、Wikidataで人間として登録され、かつ生年がわかる人物だけが表示される(判定方法は機能設計書を参照)
- [ ] 候補は最大7件まで表示する
- [ ] 各候補に「名前(生年–没年)短い説明」を表示し、同名人物を区別できる
  - 例: `織田信長(1534年–1582年)日本の戦国大名`
- [ ] 日本語の名前が登録されていない人物は英語の名前で表示し、英語の名前もなければWikidataのID(例: `Q171411`)で表示する
- [ ] 候補はマウス・タップ・キーボード(上下キーとEnter)のいずれでも選択できる
- [ ] 候補が0件のときは「該当する人物が見つかりませんでした」と表示する
- [ ] 通信に失敗したときは「データを取得できませんでした。時間をおいて試してください」と表示し、画面は操作可能なまま保たれる
- [ ] 選択済みの人物は、入力欄を編集またはクリアすることで別の人物に変更できる

**優先度**: P0(必須)

#### 2. 生存期間のタイムライン表示

**ユーザーストーリー**:
歴史を学んでいる子供として、2人が同じ時代を生きていたかを直感的に理解するために、生存期間が西暦の横軸上に線で描かれた図が欲しい

**受け入れ条件**:
- [ ] 横軸は西暦で、目盛りに年が表示される
- [ ] 表示範囲は「早いほうの生年〜遅いほうの没年」に左右の余白を加えた範囲になる
- [ ] 人物ごとに色の異なる横線が1本ずつ描かれる
- [ ] 線の上に人物名、線の両端に生年・没年が表示される
- [ ] 2人の生存期間が重なる区間は、背景を塗って強調表示される
- [ ] 1人だけ選択した時点で、その人物の線が表示される
- [ ] 1人も選択していないときは、タイムラインの位置に「名前を入力して、比べたい人物を選んでください」と案内を表示する
- [ ] 画面幅(スマホ幅360px〜PC幅1920px)に合わせて縮尺が変わり、横スクロールなしで全体が見える

**優先度**: P0(必須)

#### 3. 同時代かどうかの結果表示

**ユーザーストーリー**:
歴史好きの大人として、重なりの長さや年齢関係をすぐに把握するために、比較結果を文章で説明してほしい

**受け入れ条件**:
- [ ] 2人とも選択されると、タイムラインの近くに結果の文章が表示される
- [ ] 重なりがある場合、重なり期間と年数、年齢関係を表示する
  - 例: `1543年〜1582年の約39年間、同じ時代を生きていました`
  - 例: `徳川家康が生まれたとき、織田信長は約9歳でした`
- [ ] 重なりがない場合、先の人物の没年から後の人物の生年までの年数を表示する
  - 例: `Aが亡くなってから約○年後に、Bが生まれました`
- [ ] 年数と年齢は生年・没年の「年」の差で計算し、月日を考慮しないため「約」を付ける
- [ ] 紀元前と紀元後をまたぐ計算では、西暦に0年がないことを考慮して1年差し引く
  - 例: 前4年〜後30年の期間は33年間
- [ ] 生没年があいまいな人物が含まれる場合、結果が目安であることを補足表示する
- [ ] 没年不明の人物が含まれる場合、同じ時代かどうかを判定できないことを文章で伝える
  - 例: `〇〇の没年が不明なため、同じ時代かどうかを判定できません`
- [ ] 次の場合も、状況に合った自然な文章で表示する(文章の全パターンは機能設計書のA5を正とする)
  - 重なりが1年未満の場合(例: `1600年の1年足らずの間、同じ時代を生きていました`)
  - 先の人物が亡くなった年に後の人物が生まれた場合
  - 2人とも存命の場合(「現在まで〜生きています」と現在形で表す)
  - 2人が同じ年に生まれた場合

**優先度**: P0(必須)

#### 4. データの特殊ケースへの対応

**ユーザーストーリー**:
歴史好きの大人として、表示内容を信頼して使うために、紀元前の人物や生没年が不確かな人物でも、その不確かさがわかる形で正しく表示してほしい

**受け入れ条件**:
- [ ] 紀元前の年は「前551年」のように表記する(候補一覧、線の端、結果文章のすべてで統一)
- [ ] 存命の人物(没年データなし、かつ生年が現在から120年以内。120年は記録上の最長寿命(122歳)を目安にした値)は、現在の年まで線を引き、線の右端を矢印で表示する
- [ ] 生没年が年単位ではなく年代・世紀単位でしかわからない人物は、該当する線の端を点線で表示し、年を「1530年代」「6世紀頃」のように表記する(精度の判定方法は機能設計書を参照)
- [ ] 没年が不明と登録されている人物、または没年データがなく存命とも判断できない人物は「没年不明」と表示する
- [ ] Wikidataに生年・没年が複数登録されている場合、Wikidataで「推奨」とされている値を優先し、なければWikidataの応答に含まれる順で最初の値を使う

**優先度**: P0(必須)

### 初期リリース後の機能(P1)

#### 5. URLでの共有

**ユーザーストーリー**:
歴史好きの大人として、見つけた驚きを家族や友人に伝えるために、比較結果をURLで共有したい

**受け入れ条件**:
- [ ] 人物を選択すると、ページのURLに人物のWikidata IDが反映される
  - 例: `https://nogawa-asase.github.io/ijin-timeline/?a=Q171411&b=Q171977`
- [ ] そのURLを開くと、同じ比較結果が表示される
- [ ] URLに不正なIDが含まれる場合は、その欄を空欄にして通常どおり表示する

**優先度**: P1(重要)

#### 6. 3人以上の比較

**ユーザーストーリー**:
歴史好きの大人として、ある時代の人物関係をまとめて把握するために、3人以上を並べて比較したい

**受け入れ条件**:
- [ ] 「+ 人物を追加」ボタンで入力欄を増やせる
- [ ] 追加した入力欄は削除できる
- [ ] 入力欄には上限人数を設ける(人数はP1の着手前に決定する。今後の検討事項を参照)

**優先度**: P1(重要)

#### 7. タイムラインの見やすさ向上

**ユーザーストーリー**:
歴史を学んでいる子供として、人物が生きた時代の雰囲気をつかむために、時代区分や人物の詳細をタイムライン上で確認したい

**受け入れ条件**:
- [ ] 世紀ごとの目盛り線を表示する
- [ ] 選択した人物に合った時代区分を背景に表示する(日本の人物なら戦国時代・江戸時代、中国の人物なら王朝、ヨーロッパの人物ならルネサンスなど)
- [ ] 人物の線をタップ/クリックすると、説明文とWikipediaへのリンクを表示する

**優先度**: P1(重要)

**優先度**: P2(できれば)

**優先度**: P2(できれば)

## 非機能要件

### パフォーマンス
- **候補の表示**: 入力が止まってから1秒以内に候補一覧が表示される(一般的な家庭用回線・4G回線で)
- **タイムラインの描画**: 候補を選択してから0.5秒以内にタイムラインと結果文章が表示される
- **初回表示**: ページを開いてから2秒以内に入力可能な状態になる(4G回線で)
- **API呼び出しの抑制**: 1回の検索につき、候補検索1回+詳細取得1回(候補IDをまとめて取得)までに抑える

### ユーザビリティ
- **学習コスト**: 小学校高学年の子供が、説明なしで2人の比較を完了できる
- **レスポンシブ対応**: 画面幅360px〜1920pxで、横スクロールなしで操作・閲覧できる
- **タップ操作**: スマホでのタップ対象(候補、ボタン)は44px四方以上
- **エラーメッセージ**: 原因と次の行動がわかる日本語で表示する
  - 「該当する人物が見つかりませんでした」
  - 「データを取得できませんでした。時間をおいて試してください」
- **色の区別**: 人物の線の色は、色覚の多様性に配慮し、色以外(名前ラベル)でも区別できる
- **キーボード操作**: マウスやタッチを使わず、キーボードだけで人物の入力から比較結果の表示まで操作できる
- **スクリーンリーダー**: 入力欄・候補一覧・比較結果の文章が、スクリーンリーダーで読み上げられる(タイムラインの図の内容は比較結果の文章で伝える)

### 信頼性
- **データの不確かさの明示**: 生没年があいまい・不明なデータを推測で補わず、そのまま不確かさがわかる形で表示する
- **通信エラー耐性**: Wikidataへの通信が失敗・タイムアウト(10秒)しても、画面が壊れず、再入力で再試行できる
- **データの出典**: 画面内にWikidataを出典として表示する

### セキュリティ
- **個人情報を扱わない**: ユーザー登録・ログイン・入力内容の保存を行わない
- **外部データの安全な表示**: Wikidataから取得した文字列は、HTMLとして解釈させずテキストとして表示する
- **通信**: 外部との通信はHTTPSのみで行う

### スケーラビリティ・拡張性
- **サーバー不要**: 静的ファイルのみで構成し、GitHub Pagesで公開する。利用者数が増えてもサーバー費用が発生しない
- **入力欄数の拡張**: 入力欄の数を2から後で増やせる構造にしておく(P1の3人以上比較に備える)
- **機能追加の容易さ**: 出来事表示などの機能を、既存の描画処理を大きく変えずに追加できる構造にする

## スコープ外

明示的にスコープ外とする項目:
- ユーザー登録・ログイン、比較履歴の保存
- 人物以外(作品、建築物、国・王朝など)の期間の比較
- 日本語以外の言語での表示
- 独自の偉人データベースの構築・データの手動修正(データはWikidataに依存する)
- 生没年の月日単位での比較、和暦表記
- 自前のサーバー・バックエンドの構築

## 今後の検討事項

- **入力欄の上限人数(P1着手前に決定)**: 3人以上の比較での上限人数と、人数が増えたときの見せ方
- **表記ゆれ・別名への対応**: 「家康」「松平元康」などで目的の人物がヒットするか、プロトタイプで検証する
- **Wikidataの利用制限**: 混雑時の応答速度や、問い合わせ回数の制限にかからないかをプロトタイプで検証する
